2 ЗАВДАННЯ 
Метою лабораторної роботи є розробка мобільного застосунку як частини програмної системи для автоматизації роботи бібліотеки, а також забезпечення його взаємодії із серверною частиною через REST API та відображення архітектури за допомогою UML-діаграм.


3 ОПИС ВИКОНАНОЇ РОБОТИ 
У ході виконання лабораторної роботи було розроблено мобільний застосунок для платформи Android з використанням мови програмування Kotlin та фреймворку Jetpack Compose. Застосунок є складовою частиною програмної системи автоматизації роботи бібліотеки, архітектура якої була сформована на попередніх етапах розробки. Мобільний клієнт взаємодіє із серверною частиною через REST API, що забезпечує обмін даними у форматі JSON та відповідає клієнт-серверній архітектурі.
Функціонально застосунок реалізовано у вигляді інтерфейсу з кількома вкладками, зокрема каталогом книг, бронюванням, позиками та профілем користувача. Основні сценарії взаємодії користувача із системою відображено на UML діаграмі прецедентів (див. рис. Б.1). Згідно з цією діаграмою, користувач може виконати вхід у систему, переглядати каталог, створювати бронювання, скасовувати їх, переглядати інформацію про власний профіль та виходити з акаунту. Таким чином мобільний застосунок виступає клієнтським інтерфейсом доступу до функціоналу бібліотечної системи.
Архітектура застосунку представлена на UML діаграмі компонентів (див. рис. Б.2). Вона побудована за принципами розділення відповідальностей, де інтерфейс користувача реалізує відображення даних, ViewModel обробляє стан і логіку взаємодії, а рівень Repository відповідає за отримання даних із серверу. Передача даних відбувається послідовно: від інтерфейсу користувача до ViewModel, далі до Repository, після чого формується запит до REST API, який передається на сервер. Сервер обробляє запит, взаємодіє з базою даних і повертає результат, який відображається у застосунку.
Основні сценарії роботи користувача із застосунком відображено на UML діаграмі діяльності (див. рис. Б.3). Після запуску застосунку користувач проходить авторизацію. У разі успішного входу відкривається доступ до функціоналу перегляду каталогу. Користувач може обрати книгу та створити бронювання, після чого відповідний запит надсилається на сервер і повертається підтвердження. Також передбачено можливість скасування бронювання: користувач обирає відповідний запис, ініціює запит на скасування, після чого сервер оновлює стан даних, а застосунок відображає актуальний список бронювань. У випадку помилки авторизації або виконання операції користувачу виводиться повідомлення про помилку.
Взаємодія між мобільним застосунком та серверною частиною системи детально відображена на UML діаграмі взаємодії (див. рис. Б.4). Наприклад, під час створення бронювання користувач ініціює запит у застосунку, який передається через REST API на сервер. Сервер виконує обробку запиту, звертається до бази даних для збереження інформації та повертає відповідь у вигляді JSON. Отримана відповідь передається назад у застосунок, де відображається користувачу. Аналогічним чином відбувається і скасування бронювання.
У застосунку реалізовано лише клієнтську логіку, тоді як основні бізнес-процеси, такі як обробка бронювання, зміна статусів книг і створення позик, виконуються на сервері, що забезпечує цілісність даних та узгодженість роботи всієї системи. Функціонал роботи з позиками на даному етапі реалізований частково, оскільки його повна підтримка залежить від завершення розробки веб-інтерфейсу адміністратора, який відповідає за оформлення видачі книг.
Назва інструменту та версія: модель GPT-5.3, план Go.
Мета використання: Використання ШІ було необхідне через відсутність досвіду роботи з Android, Kotlin та Jetpack Compose. ШІ допомагав зрозуміти архітектуру додатку, роботу з Retrofit, ViewModel, навігацію та швидко реалізувати функції бронювання книг.
Внесок автора: Я самостійно підключила додаток до власного бекенду на Flask, адаптувала ендпоінти під свою базу даних, виправляла помилки компіляції, тестувала запити, налаштовувала AndroidManifest.xml для мережевих дозволів та адаптувала інтерфейс під вимоги лабораторної роботи.

13     suspend fun login(email: String, password: String): Result<LoginResponse> = try {

 17 @Composable

 42             Text(reservationMessage ?: "")
 43         }
 44     }
 45 
 46     Column(modifier = Modifier.fillMaxSize()) {
 47         OutlinedTextField(
 48             value = searchQuery,

 56                 .padding(16.dp),
